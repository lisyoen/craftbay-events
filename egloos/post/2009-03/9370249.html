TCP Close Shutdown

TCP 프로토콜은 서로의 세션을 종료(close)할 때 4번의 데이터 교환을 하는데, 이를 4 hand-shaking이라 한다. 참고로, 연결(open)할 때는 3 hand-shaking을 사용한다.

 소켓의 종료 과정은 아래 설명처럼  FIN ACK FIN ACK 과정을 거치는 4 hand-shaking이 일어난다. 먼저 클라이언트에서 close()를 호출하면 곧 바로 코드로 반환됨과 동시에 커널의 TCP 모듈이 서버로 FIN을 전송한다. 서버가 FIN을 받으면 read()함수가 0을 리턴하며, 프로그래머는 이 때  클라이언트에서 종료 요청이 왔다는 것으로 인식할 수 있다. 이제 서버의 close()함수를 실행하면 다시 클라이언트로 FIN을 보내고 클라이언트에서 다시 ACK를 보내면서 종료 과정이 마무리된다.
 이 후 일어나는 3번의 hand-shaking은 이제 응용프로그램의 범위를 벗어나 커널의 소켓 라이브러리에서 이루어지므로 프로그래머가 고려할 사항이 아니다.

 shutdown은 close와 달리 read, write 중 하나만 종료할 수 있는 부가적인 기능을 제공한다. 여기서 read, write란 TCP 모듈의 읽기 버퍼와 쓰기 버퍼에 관련된 작업을 뜻한다.

shutdown(socket 디스크립터, (SHUT_WR|SHUT_RD|SHUT_RDWR)) 

 아래 설명은 클라이언트에서 쓰기만 닫는 상황을 보여주고 있다. shutdown(sd, SHUT_WR)을 호출하면 우선 2단계 hand-shaking이 일어난다. 이때 서버쪽에서 FIN을 수신하므로 서버쪽의 read()함수는 0을 리턴한다. 그리고 서버 커널의 TCP모듈은 클라이언트로 ACK를 발송한다. 이 상황에서 클라이언트는 아직 읽기 작업을 할 수 있다. 아직 서버에서 FIN이 오지 않았기 때문이다. 그리고 소켓의 write 기능은 shutdown(sd,SHUT_WR)을 호출했으므로 사용할 수 없는 상태다. 이 후 서버에서 close()를 호출하여 FIN이 클라이언트로 도착하면 클라이언트의 read()함수는 0을 리턴하고 ACK를 전송하게 된다. 마지막으로 클라이언트가 close()를 호출하고 끝난다.

1. 클라이언트에서 close()함수 호출시 동작 (4hand-shaking)
  클라이언트에서 close()호출(즉시 반환) -> 
  커널의 TCP 모듈에서 FIN 발송 ->
                                                                  FIN 수신 후 서버의 read()함수가 0을 리턴
                                                                  <- 커널의 TCP 모듈에서 ACK 발송
                                                                  <- close()호출. 커널의 TCP 모듈에서 FIN 발송  
  커널의 TCP 모듈에서 ACK 발송 ->
 
2. 클라이언트에서 쓰기만 닫는 shutdown()함수 호출시 동작 (2hand-shaking)
  클라이언트에서 shutdown()호출(즉시 반환, read()대기) -> 
  커널의 TCP 모듈에서 FIN 발송 ->
                                                                  FIN 수신 후 서버의 read()함수가 0을 리턴
                                                                  <- 커널의 TCP 모듈에서 ACK 발송
                                                                  <- write() 로 데이터 송신
                                                                  <- close()호출하면 커널의 TCP 모듈에서 FIN 발송  
  read()로 데이터 수신
  read() 함수가 0을 리턴
커널의 TCP 모듈에서 ACK 발송 ->

  그렇다면, close대신 shutdown을 쓰는 이유는 무엇일까? 위에서 보다시피 클라이언트에서 close()를 호출하면 TCP의 read, write 버퍼가 모두 봉쇄되므로 더 이상 서버에서 데이터를 받을 수도 서버로 보낼 수도 없다. 

  그러므로 클라이언트가 서버로(혹은 반대 방향으로) '이제 나는 종료할거야'라는 메시지를 전달하고 서로 마지막 데이터를 송, 수신할 필요가 있을 때 shutdown을 사용하면 된다는 것을 알 수 있다.

P.S) 그런데, 같은 방법으로 client에 shutdown(sd, SHUT_RD)를 실행하여 읽기만 종료하고, 서버로 write하였다. 그럼 서버측에서는 shutdown()에 대응하는 read()가 0을 리턴한다.  다시 read()를 호출했더니 계속 수신 문자수가 0으로 나온다. 즉, shutdown 후의 write 내용을 수신받지 못하는 것이다. 계속 조사해 볼 필요가 있을듯 하다.
