Non Trade-off 관계





Trade off 란 '교환하다' 라는 뜻의 숙어로 실생활 에서는 교환 관계를 의미한다.



Trade-off 관계란 두 상태의 저울질을 뜻하는 것으로 적당히 균형을 맞춰야 하는 관계로

풀이할 수 있다. 다음과 같은 것들이 Trade-off 의 대표적인 예이다.



- 연탄의 구멍 수 (구멍이 많으면 화력은 좋지만 빨리 타서 새벽에 춥다: 하루밤을 버틸만큼만 구멍을 만든다)

- 광고와 수익률 (광고가 많으면 수익이 늘지만 너무 많으면 광고 비용 때문에 수익이 줄어든다. 수익이 최고점이 될 수 있는 만큼만 광고를 한다 )

- 품질과 비용 (품질을 높이기 위해서는 비용이 많이 든다. 소비자가 수용할 수 있는 가격 선에서 품질을 높인다)



프로그래밍에서는 흔히 '속도와 용량' 이 Trade-off 관계로 대표된다.

즉, 빠른 속도를 위해서는 큰 용량의 메모리를 소모해야 한다는 것이다.

반대로 메모리 사용을 줄이면 속도가 저하된다.



이것은 거의 모든 알고리즘과 자료구조에 적용되는 내용으로 특별한 상황(특정 하드웨어에 이식하는 프로그램, 극단적으로 메모리나 CPU를 많이 사용하는 프로그램 등)을 제외하고는 메모리를 희생해 속도를 향상시키는 것이 선택되어 진다.



속도를 우선시 하는 Trade-off 가 이처럼 당연시 되고 있지만 사실 컴퓨터는 이러한 Trade-off 를 용납하지 않는 경우가 많다.

예를 들어 1GHz 의 CPU 와 256MB 메모리에서 원활히 작동하는 프로그램이 있을 때 메모리 소모를 2배로 늘려 CPU 적정 사양을 500MHz 까지로 낮춘다고 생각해보자.



1GHz CPU 와 256MB 의 메모리는 일반적이지만

500MHz CPU 와 512MB 의 메모리는 다소 일반적이지 않다.



심지어 256MHz 의 CPU 에서도 작동할만한 속도를 갖기 위해 1GB 의 메모리를 사용해야 한다면. 이러한 Trade-off 는 오히려 사용 가능한 컴퓨터의 폭을 제한하는 결과를 낳게 된다.



속도를 최우선으로 하는 프로그래밍이지만 결국 Trade-off 관계란 어느 한쪽이 일방적으로 우선시 되지 않는 것을 뜻한다. 품질에 최선을 다해 소비자와 동떨어진 가격을 형성하는것은 결코 Trade-off 라고 할 수 없다.



극한의 속도와 메모리를 사용하는 게임 프로그래밍에서는 이것을 간과해서는 안된다.
